# CivicTrack audit and verification — 19 October 2026

## Outcome and scope

Confirmed defects were fixed in the existing Expo/React Native, Express/MongoDB and FastAPI/YOLO application. The existing design, navigation and role separation were preserved. The audit began on 18 October and continued on 19 October; evidence is stored under `mobile/tests/artifacts/audit-2026-10-18/`.

The supplied master-task attachment ends mid-sentence in Phase 4. This report covers the requirements actually supplied. Passing checks establish the behavior described below; they do not prove that every possible defect or device-specific issue has been eliminated.

The current source inventory contains 139 files under `mobile/src`, `backend/src` and `ai-service/app`.

Generated dependencies and model binaries were exercised where relevant rather than treated as application source. No dedicated lint script or CI workflow was found. ## Confirmed fixes

| Problem / root cause | Result and main files |
| --- | --- |
| Complaint titles and addresses were interpolated into map popup HTML. Web messages were accepted from unrelated windows. | Popups use DOM `textContent`; web messages must come from the actual map frame. Coordinate and selected-pin messages are validated. The web iframe is sandboxed. `mobile/src/components/MapSurface.web.tsx`, `MapSurface.tsx`. |
| The web map iframe ref callback caused unnecessary state changes. Failed external map resources could leave a blank preview indefinitely. | Stable ref; a 12-second tile-readiness timeout displays coordinates, Retry and an external-map action. Retry reloads the preview. The native preview has the same readiness timeout and retry. Missing Leaflet is handled without an unhandled reference error. |
| Category/location changes overwrote citizen-written descriptions. Concurrent GPS/geocode requests could restore old coordinates/addresses. | Citizen edits survive subsequent category/location changes; Reset explicitly regenerates a draft. Request generations reject stale results; cleanup invalidates outstanding requests. Only confirmed addresses enter generated text. `ReportIssueScreen.tsx`, `DescriptionEditor.tsx`. |
| AI fallback text could describe a pothole while the category was Other; retaking a photo could leave a blank draft. | Unsupported categories normalize to Other, stale AI failures are ignored, and retaking resets generation consistently. Coordinates are checked before submission. |
| Inference exceptions were swallowed and could look like a successful no-detection result. Suppression could remove overlapping issues of different categories. | Model failures produce service-unavailable responses; suppression compares the same category only. `ai-service/app/detector.py`. |
| RGB NumPy image input conflicted with Ultralytics' BGR convention for arrays. | Pass a PIL image through the documented loader path. A regression checks the input type/color handling. |
| Blocking inference ran inside an async FastAPI handler; image reads had no application-level size bound. | Synchronous endpoint runs in FastAPI's thread pool, reads at most 10 MB plus one byte and rejects oversized images; unexpected errors return a generic response and are logged. Settings use the current Pydantic configuration form. `app/main.py`, `app/config.py`. |
| New passwords could exceed bcrypt's 72-byte limit; complaint text/confidence/bounding boxes had validation gaps. | Registration/password-change inputs enforce the UTF-8 byte limit; text is trimmed before validation, confidence is finite/in range, and boxes must be finite, nonnegative and ordered. Existing login compatibility is preserved; old password hashes are not migrated. `backend/src/validators/*`. |
| A random complaint-reference collision failed complaint creation. | Retry only the complaint-reference unique-key collision, with a bounded retry count. `complaintController.ts`. |
| Officer verify/status responses returned an unpopulated citizen reference. | Mutation responses populate citizen contact fields, retaining them in the detail UI. `authorityController.ts`. |
| Select All compared record counts instead of visible record identities. | Filtered selections correctly union/remove visible IDs; checkbox labels and checked state are exposed. `AuthorityComplaintsScreen.tsx`. |
| Selected filter/navigation controls lacked valid web state attributes; narrow description headers could crowd. | Button selection uses `aria-pressed`, checkboxes expose `aria-checked`, and description labels wrap. Dashboard accessibility violations now fail the test. Shared selectors/sidebars and `DescriptionEditor.tsx`. |
| GPS/geocoder timeout handles survived completed/failed requests. | Timers are cleared in `finally`. `mobile/src/services/location.ts`. |

The initial fixes are present in repository commit `8086e6f`; this continuation adds map recovery, stronger live-test selectors, configurable browser-test URLs, a focused map runtime test and final evidence. No commit or deployment was created in this continuation.

## Reproduce checks

Run backend build/tests from `backend`, mobile checks from `mobile`, and pytest from `ai-service`.

```powershell
# backend
npm run build
npm test

# ai-service (installed local runtime)
& ./.venv/Scripts/python.exe -m pytest -q

# mobile, with the local Expo web server already running
npm run type-check
$env:CIVICTRACK_WEB_URL='http://localhost:8082'
npm run test:e2e
node tests/e2e/map-runtime.cjs
npx expo export --platform android --output-dir .expo/audit-android-20261019 --max-workers 2
```

`live-audit.cjs` additionally requires the isolated loopback backend, AI service, local MongoDB and its audit-only Officer fixture. It intentionally rejects a non-loopback backend or any port other than 5099:

```powershell
$env:CIVICTRACK_AUDIT_API_URL='http://127.0.0.1:5099/api'
node tests/e2e/live-audit.cjs
```

## Remaining configuration and verification limits

### Follow-up: Authority browser map access block

The user subsequently reported an access-blocked map in the browser. The web map's opaque-origin sandbox could suppress the browser referrer expected by the tile provider. The iframe now retains the page origin and explicitly uses `strict-origin-when-cross-origin` for frame/tile requests. A generated per-mount nonce and frame Content Security Policy restrict executable scripts; complaint text still uses `textContent` and bridge messages still verify the sending frame. No tile proxy, provider rotation or access-block bypass was introduced.

The focused browser test verifies the real tile-request `Referer` header, Leaflet/OSM rendering, retry recovery, and rejection of an injected script without the nonce. The map popup/message/bulk-selection regressions and mobile TypeScript check also pass. This addresses a confirmed integration defect; without the user's original network response, an additional provider/IP restriction cannot be ruled out.

### External configuration and device checks

- Google client IDs are absent in the inspected local configuration. Live Citizen/Officer Google OAuth needs Google Cloud credentials, correct Android signing fingerprints and a rebuilt APK. Automated token/role/linking coverage does not establish live Google sign-in success.
- Cloudinary credentials are absent. Production storage availability remains unverified; tests confirm failure is reported instead of returning a misleading success.
- The preview EAS profile targets a private LAN API. No public HTTPS backend was deployed or verified by this audit. Release profiles require an explicit HTTPS API URL.
- No physical Android device was connected. Native camera/gallery permissions, keyboard, system bars/cutouts, WebView behavior, GPS and current installed-APK login require device testing. Browser dimensions approximate screen space, not a Vivo hardware test.
- The four models execute, but no labeled evaluation dataset or accuracy report was established. Confidence is not proof of accuracy. Descriptions remain editable citizen-reviewed drafts.
- Map CDN, tile and geocoding availability can vary. The recovery state handles failure; it does not make these services available offline.
- Notification preferences are local application settings; no live push-delivery service was verified. An unused legacy Authority header contains mock notification data but is not mounted by the current navigation.
- No new APK, public deployment, live OAuth result or production-ready guarantee is claimed. The available checks passed within the scope above.
